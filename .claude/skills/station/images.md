# Compiled Station Images

Use `station-images` when code is authored independently of Station's TypeScript builders. The image contains a `station.image/v1` manifest and content-addressed artifacts; it does not contain an OS filesystem. Read the [complete guide](https://github.com/porkytheblack/station/blob/main/docs/STATION-IMAGES.md) for runnable authoring examples and the bounded protocol/schema contracts.

## Authoring and configuration

- Native programs must be compiled for declared OS/architecture/ABI; bundled JavaScript declares `node` or `bun` plus minimum runtime major. Bun standalone output is native. Publish prebuilt files with exact SHA-256 digests and sizes; `images build` hashes explicit precompiled files and `pack` verifies/copies them. Neither runs a compiler or remote build script. The publisher uses resumable sessions and private local receipts; rerun the same command to reconcile an uncertain remote offset before more chunks.
- Exports are signals, binary broadcast planners or beacons. Finite programs read an NDJSON `station.process/v1` invocation and emit a result. Broadcasts return a declarative DAG referencing sibling/image signals or explicitly granted revision-pinned operator Station bundles; the saved plan survives restart. Beacons use the long-lived protocol and scoped dependency broker. Do not invent nested broadcast DAG nodes or arbitrary JavaScript plan expressions.
- Configure daemon `registry.rootDir` (filesystem default) or `registry.storage: { id, metadata, blobs }`, plus `registry.execution`. `ImageRegistry` enforces shared policy; built-in file/memory adapters implement `RegistryMetadataAdapter` and `RegistryBlobAdapter`. PostgreSQL/S3 registry drivers are not bundled. Custom adapters need bounded reads, atomic immutable creation, read-after-write consistency and cross-writer blob quota admission. Storage namespace IDs must be stable and non-secret; changing one requires activation reconciliation. Custom storage uses a verified local `registry.cacheDir` for child execution, keeping provider credentials in the daemon. Complete pinned caches support offline recovery; moving tags still resolve at the authority.
- Docker policy belongs to the operator: digest-pinned Linux runtime, compatible target, non-root, read-only filesystem, no network, resource limits and seccomp. Engines with an unconfined default need an explicit reviewed deny-default `seccompProfile`. Trusted-local execution needs explicit unsafe opt-in and is unsuitable for uploaded untrusted code.
- Grant environment keys through `registry.execution.allowedEnv` and the daemon environment store; manifests can declare required/default values. There is no arbitrary direct `/registry/run` environment override or implicit controller-secret inheritance. Deployment stage may explicitly grant `invocationEnv` keys; `/deployments/:id/run` accepts `environment` bindings only within that allowlist and records a retained derived generation/history.invoke without moving the active alias pointer. Deployment generations accept bindings `{value: nonSecretString}` or `{fromEnv: grantedStoreKey}`; both source and destination keys need grants. References resolve current scoped store values per attempt, not immutable secret revisions.

## CLI and network workflow

```sh
station images publish ./station-image.json --artifacts-dir ./build --context headquarters
station images inspect acme/tools@1.0.0 --context headquarters
station images install acme/tools@1.0.0 --context headquarters
station images run acme/tools@1.0.0 echo --input @request.json --context headquarters --station coding-worker
```

Use an authenticated admin context. References use `name@version`, `name@tag` or a digest, not Docker colon tags. Run returns an ID and does not imply waiting. APIs under `/api/v1/registry` include blobs, images, resolve, tags, pull, install and run; run accepts `{reference, export, input, stationId?}`.

Configured workers synchronize the Headquarters catalog. Default eager mode installs compatible closures; `upstream.mode:"on-demand"` advertises finite definitions, then uses separate preparation leases to fetch/verify/install before execution claims. Images containing beacons remain eager. `/registry/preparations` shows local bounded in-memory observations. Shared durable queues/membership remain necessary. Unsupported targets skip; corrupt blobs/records or invalid grants fail explicitly. Tenant registry namespaces exist separately from the operator catalog and require mapped registry-only keys.

Contexts choose endpoints; optional `--station` pins signal execution and broadcast planner/children durably. Headquarters can create pinned shared beacon instance intent for eligible workers; it does not run beacon processes itself. Pins do not silently move on worker failure. Tags affect future requests; retain immutable definitions and blobs needed by queued runs and plans.

## Cleanup and verification

Deployments retain immutable generations with aliases, worker pin and environment bindings. Use `deployments stage|inspect|activate|rollback|drain|rollout|run` with actual API JSON bodies; activation/rollback/drain require `expectedRevision`. Existing runs and beacon instances are not replaced by activation. Explicit `rollout` accepts `{operationId,expectedRevision,sourceInstance,generation,alias}` for a previously activated beacon generation; it durably stops the source before creating a deterministic replacement and retains the old incarnation. Reuse the same operation ID after uncertain responses and inspect deployment.rollouts; readiness marks completion. This may have downtime and does not version the secret store. No reference-aware artifact GC exists.

For non-run image commands, `--station` selects an operator-configured private registry proxy target; for `images run` it remains execution placement. Tenant `--tenant` routes use `/tenant/registry` and cannot forward to arbitrary Station targets. Tenant scopes are exactly `registry`, with independent read/publish/activate/invoke grants. Use createTenantRegistryWorkerGateway for execution through a fixed dedicated tenant worker: it verifies worker/tenant/namespace identity, imports pinned dependencies and invokes with immutable placement. The operator still provisions distinct queues, storage, environment and runtime/network policy. Real Docker fixture evidence exists; production-host isolation/failover remains unverified.

Run `station-image-reaper --config /etc/station/image-reaper.json --interval-ms 5000` as an independent host service with the same Docker options/root directory. Journals and matching container labels protect ownership; expiry cleanup still works after controller death. Runtime timeout alone is not sufficient for hostile code. Reaper config contains no invocation credentials and must be a regular file without group/world write access.

The source checkout has real Docker integration tests for native/JS execution, isolation settings, timeout cleanup and independent reaping. They are opt-in and skipped checks are not validation. See the complete guide for fixture compilation and environment variables. Production host/fleet/storage recovery requires its own acceptance; operator APIs, containers and version 3.0 do not establish public multi-tenant readiness.

Enrollment is separate from contexts/shared adapter credentials: the authority issues network/worker-bound single-use invitations, rotates opaque worker credentials and durably revokes them. Worker admission checks fail closed. Daemon claims, heartbeat/renewal and active children use fresh admission checks. A real daemon revocation test proves active work stops and later heartbeats cannot re-admit the worker. Use `network invite ID --out FILE`, `network join --file FILE|- --out WORKER_CONFIG`, `network members`, `network revoke ID`, and `network leave --file WORKER_CONFIG|-`. Files are mode0600, outputs contain no secret, and join/leave use the file’s fixed authority/identity rather than context or URL overrides. Enrollment does not provision shared adapters or copy database credentials. Operator TUI event reconnect preserves bounded replay cursors and verifies daemon identity; tenant views poll without the global feed. Stream reset means reconcile state, not replay mutations. Nested TUI workspace files/terminals/services/command receipts and browser pages/profiles/recordings/diagnostics/checkpoints/artifact receipts use the same owner-scoped APIs. Command/artifact history is receipts observed by this TUI, not a global server history. Visual playback stays in the dashboard; local binary files use CLI helpers.

## Native planner grants and invocation files

An image manifest can declare `nativeSignals: {alias:{name,revision}}`; matching `registry.execution.nativeSignals` entries are operator-owned `{name,revision,file,selfContained:true}`. Revision is the bundle digest. The bundle must default-export the matching ordinary Station signal and include application dependencies; only `station-signal` may be external. Uploads never choose local module paths. Station verifies immutable cached bytes at bootstrap. These trusted operator definitions retain ordinary Station privileges; they are not uploaded untrusted code.

Exports may declare `artifacts:{read?,write?}`. Configure `registry.execution.artifacts` with `rootDir`, static `grants` indexed by `imageDigest + "#" + exportName`, and bounded per-scope/global limits. A grant contains `readReferences` and/or `write:true`. Input strings never self-authorize a reference. The process broker accepts correlated `artifact:request` create/append/commit/read operations and replies with `artifact:response`; append/read payloads are bounded base64 chunks. Finite scopes bind run/attempt, beacon scopes bind instance/incarnation. `FileInvocationArtifactStore` has SDK scope/handle/close/reapExpired APIs for operator import/read; the daemon reaps expired media every 60 seconds. There is no media HTTP upload/download endpoint, automatic cross-worker transfer or distributed storage driver. Use separate tenant roots; explicit shared filesystem access and grants are required across workers. Never confuse invocation-file expiry cleanup with reference-safe executable image GC.

The dashboard now selects a fixed private registry via Headquarters, retains that target through nested pages and invokes private images on that worker. It supports resumable chunks with tab-scoped receipts/Pause/Resume and a generation binding editor (references or explicitly non-secret literals). Resolved secret values are never fetched for review. The connected daemon registry has separate execution placement. CLI `images run --station` remains an execution pin in its selected context; use a direct worker context to run a private-only image via CLI.

Production Linux validation was explicitly deferred because the target is unavailable. Report that limitation and final release-preflight evidence separately; npm publish rights remain unverified until authenticated preflight succeeds. The native Docker beacon fixture passed; see the acceptance map for remaining operational and release checks.

For automation, sandbox `exec --wait [--wait-timeout-ms 300000]` polls one accepted command and preserves remote exit status; default exec stays asynchronous. Local timeout 124/Ctrl-C 130 stop waiting without cancelling and print the last result. Remote timeouts use the command JSON `timeoutMs`; explicit cancel uses the receipt runId. Global `--json-errors` emits safe `{error:{code,status,message}}` on stderr; no automatic mutation retries.
