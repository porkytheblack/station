# Station Images acceptance map

This is a review map for the numbered requirements in [the Station Images plan](plans/station-images.md#implementation-sequence-and-acceptance), as of 2026-09-21. It separates implemented behavior, executable evidence and remaining acceptance work. It is **not** a declaration that the complete public multi-tenant platform is production-ready.

A test file's presence is evidence of a reproducible case, not proof that its latest revision passed. Opt-in Docker/browser tests must run without skips. The final coordinated `pnpm release --dry-run --allow-dirty` passed all 20 packages without skipping checks. The final source-doc synchronization is verified separately below; live publish access is not established by that dry run.

## Remaining plan and release acceptance

1. **Current artifact transport limits (beyond the initial scoped broker):** the process broker and daemon scopes work with static per-export grants and a local filesystem store. There is no general media HTTP upload/download API, automatic output-reference authorization for later jobs, cross-worker transfer service or distributed media storage driver. Operator SDK import/read and explicit shared filesystems are the current path. Do not describe image blob replication as runtime-media replication.
2. **Interaction evidence boundaries:** the TUI has specialized workspace/browser/registry/deployment views, details, confirmed actions and safe reconnect, plus separate CLI PTY/file/browser helpers. Its command/artifact lists are observed receipts, not unsupported global history APIs; graphical playback remains in the dashboard. An exhaustive matrix of every method/provider, tenant denial, unsupported capability and human lease recovery is not recorded. The [command map](STATION-CLI-COVERAGE.md) identifies the actual evidence. The dashboard uses CLI/API for explicit live beacon rollout.
3. **Defined persistence limits:** secret references deliberately resolve current scoped values per attempt; there is no versioned secret snapshot API. Preparation observations and SSE replay are not durable audit logs. The tenant gateway provisions no general scheduler or independent database credentials; storage/queue/network ownership remains operator policy.
4. **Intended-host verification explicitly deferred:** the user skipped unavailable Linux staging. Intended-host syscall/egress controls, storage/queue isolation, quotas, independent reaping and production-adapter failover remain unverified. Real Docker Desktop, SQLite process-kill and dedicated-worker fixtures establish their tested paths only. No new staging host is provisioned.
5. **Final release acceptance:** coordinated build/checks/packed installs and all 20 package dry runs passed. Final site/LLM generation and agent skill validation also passed after the latest documentation edits. Authenticated npm ownership remains unverified until login/preflight succeeds. No npm publication or StationKit deprecation has been performed. Keep automatic executable-artifact GC disabled until retained references can be proven safe.

Native Docker beacons, ordinary Station planner grants, actual controller/preparation SIGKILL recovery, enrollment admission/revocation, invocation environment auditing and explicit beacon replacement are now implemented with focused executable evidence; they must not remain listed as absent. A VM backend, managed hosted builds, extra language SDKs and automatic artifact GC remain separately scoped enhancements. The explicitly deferred production evidence remains unverified. Current scope limits are not promises of extra platform features; any remaining interfaces explicitly required by the plan are tracked separately from those limits.

After the coordinated preflight, specialized TUI views passed a 33-test CLI suite (eight TUI model cases), build/typecheck and real PTY nested owner/session/pages navigation with a confirmed page action.
